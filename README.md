# mymo

SolidJS와 TipTap으로 만든 개인 메모·할 일 웹앱입니다. 페이지와 하위 페이지, 표, 이미지, 다단 배치, 반복 블록 삽입과 날짜 도구를 제공합니다.

## 실행 및 검증

Node.js 22.12 이상과 pnpm 9를 사용합니다.

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm build
```

`master`에 반영하면 테스트와 빌드를 통과한 뒤 GitHub Pages의 `/mymo/` 경로로 배포합니다. PR에도 자동 검사를 실행합니다.

## 자료 저장과 계정 전환

- 로그인하지 않으면 이 브라우저의 IndexedDB에 저장합니다.
- Google 계정별로 별도의 IndexedDB를 사용합니다. 로그아웃해도 해당 계정의 자료를 삭제하지 않으며, 다른 계정의 작업 공간으로 자동 복사하지 않습니다.
- 계정 분리 도입 전에 저장한 기존 자료는 원래 DB(`ssaemlinderDB`)에 그대로 남아 있으며 **로그아웃 상태에서 볼 수 있습니다**. 이 자료의 소유자를 자동으로 추정하거나 다음 로그인 계정에 업로드하지 않습니다.
- 기존 기기 자료를 계정으로 옮기려면 원하는 계정으로 로그인한 뒤 설정 → 이전 기기 자료를 계정으로 복사를 선택합니다.
- 다른 기기도 최신 화면으로 새로고침해서 사용하세요. 이전 버전 클라이언트는 새로운 동기화 규약을 따르지 않습니다.

## 저장 및 여러 기기 동기화

- 본문 입력 시 바로 로컬 저장 트랜잭션을 시작합니다. 페이지 이동·로그아웃·계정 보관은 대기 중인 쓰기가 완료된 뒤 진행합니다.
- 로컬 변경과 업로드 대기 항목을 하나의 IndexedDB 트랜잭션에 저장합니다. 네트워크가 끊기거나 탭을 다시 열어도 업로드 대기는 남습니다.
- 로그인 시 로컬 자료와 클라우드 자료를 양방향으로 병합합니다. 온라인 복귀와 15초 간격으로 재시도하며, 상태 표시줄에서도 수동 재시도할 수 있습니다.
- Firestore 트랜잭션에서 기준 revision을 검사합니다. 다른 기기가 먼저 변경했다면 본문을 조용히 덮어쓰지 않고 `충돌 복사본`을 별도 페이지로 보존합니다. 복사본은 루트에 표시되며 다시 동기화됩니다.
- 영구 삭제는 내용을 비운 삭제 기록(tombstone)으로 전파합니다. 최신 클라이언트의 오래된 로컬 사본으로 같은 ID를 재생성하지 않습니다. 삭제와 동시에 다른 기기가 수정했다면 해당 수정은 별도 복사본으로 보존합니다.
- 다른 기기의 변경은 열려 있는 편집기와 목록에도 반영됩니다. 페이지 순서 변경도 revision과 변경 시각을 갱신합니다.
- 자신의 하위 페이지 아래로 이동할 수 없습니다. 서로 다른 기기의 이동으로 순환이 생기면 동일한 기준으로 연결 하나를 해제하고 모든 문서를 보존합니다.
- Firebase 로그인·규칙·용량 제한 등으로 전송이 실패하면 기기 자료와 대기 항목을 유지하고 실패 상태를 표시합니다. 상태의 ‘기기에 저장’은 브라우저 저장소 기준이며 외부 백업을 의미하지 않습니다.

Firestore의 실제 접근 규칙은 이 저장소에서 배포하지 않습니다. 사용자별 `users/{uid}/pages`와 기존 `folders` 접근이 인증된 해당 사용자에게만 허용되어 있는지 Firebase 설정에서 관리해야 합니다.

## 불필요한 충돌 복사본 방지

- 저장 후 화면 갱신은 백그라운드 갱신에 취소되지 않도록 순서대로 완료합니다.
- 저장이 끝난 이전 revision의 지연 응답은 현재 문서와 기준 revision을 되돌리지 않습니다. 초기 가져오기 후 실시간 구독을 시작하고, 스냅샷은 수신 순서대로 처리합니다.
- 편집기는 저장 하나가 진행되는 동안 최신 초안을 대기시킵니다. blur·페이지 이동·pagehide가 이미 진행 중인 쓰기를 중복 실행하지 않으며, 재시도는 마지막으로 저장에 성공한 값을 기준으로 합니다.
- JSON 키 순서나 생략된 null 속성 차이는 내용 수정으로 보지 않습니다. 본문 수정과 순서 변경, 제목 수정과 본문 수정처럼 서로 겹치지 않는 변경은 기준 내용과 비교해 병합합니다.
- 같은 항목을 양쪽에서 실제로 다르게 바꾼 경우의 보호는 유지합니다. 같은 원본 revision은 한 번만 복사하며, 기존 충돌 복사본을 자동 삭제하거나 덮어쓰지 않습니다.

## 무료 계정 복원 기록

JSON 백업 다운로드·자동 다운로드·파일 불러오기를 제거했습니다. PDF/PNG/Markdown/텍스트 문서 내보내기는 유지합니다.

- Google 로그인·인터넷 연결 상태에서 앱이 열려 있는 동안 10분 간격으로 계정의 Firestore에 복원 시점을 보관합니다. 접속 직후와 온라인/화면 복귀 시에도 해당 10분 구간의 기록을 확인합니다. 여러 기기는 계정별 lease를 공유해 중복 보관을 줄입니다.
- 앱이 모두 닫힌 동안에는 작업을 실행하지 않습니다. Spark에서 Cloud Functions 예약 실행이나 유료 TTL을 사용하지 않으며, 과금 요금제 전환·새 서버·Cloud Storage 버킷 설정도 수행하지 않습니다.
- 설정 → **복원 기록 열기**에서 1/6/24시간 전 또는 직접 시각을 선택합니다. 요청 시각 이전에 실제로 저장된 가장 가까운 시점을 보여줍니다. 기능 도입 이전의 기록이나 앱이 닫혀 있던 시간의 새 기록은 만들 수 없습니다.
- **이 페이지 복원**은 현재 페이지 ID와 위치·순서·하위 페이지·다른 페이지를 유지하며 제목과 본문만 바꿉니다. 휴지통 페이지는 되살리고, 영구 삭제된 ID는 재사용하지 않고 새 ID로 복구합니다.
- **작업 공간 전체 복원**은 해당 시점의 전체 페이지 구성으로 교체합니다. 살아 있는 ID는 유지하며, 영구 삭제된 ID와 그 내부 링크는 함께 재연결합니다.
- 복원 직전 상태를 계정에 추가 보관한 뒤 로컬 자료를 한 트랜잭션으로 변경합니다. 직전 보관이 실패하면 복원을 시작하지 않습니다. 복원 후 네트워크가 끊기면 로컬 복원과 영속 전송 대기는 남습니다.
- 기존 기기 자료는 로그인 후 설정의 **이전 기기 자료를 계정으로 복사**에서 명시적으로 가져올 수 있습니다. 현재 계정 자료나 이전 기기 원본을 삭제하지 않습니다.

### 보관 기간과 용량

- 보관 시점과 만료 정리는 Firestore에서 확인한 서버 시간을 기준으로 합니다. 기기 시계가 틀려도 다른 기기의 정상 기록을 조기 삭제하지 않습니다.
- 7일 지난 복원 시점은 다음 접속/보관 작업에서 삭제하고 UI에서도 선택할 수 없습니다. 참조되지 않는 내용 조각은 하루 한 번 회수합니다. 앱이 모두 닫힌 동안의 정확한 시각 삭제는 보장하지 않습니다.
- SHA-256으로 같은 내용과 이미지를 공유합니다. 이미지 데이터는 본문과 분리해 중복 보관을 줄이고, 큰 내용은 작은 조각으로 나눕니다. 반복 삽입 템플릿의 이미지도 포함합니다. 내용은 복원 전에 해시로 검증합니다.
- 복원 이력은 내용 기준 64MiB 또는 5,000개 내용 객체를 상한으로 둡니다. 한도를 넘으면 새 보관을 멈추고 오류를 표시하며, 현재 원본이나 7일 이내 기록을 임의로 삭제하지 않습니다. 이 한도는 Firestore 전체 사용량/메타데이터/다른 앱 사용량을 대신하지 않습니다.
- 성공한 보관 시각과 실패 원인은 설정에 표시합니다. 로그인만 했거나 코드가 배포되었다고 실제 보관에 성공했다고 표시하지 않습니다. 무료 Firestore 일일 사용량 한도나 접근 규칙으로 실패하면 재시도할 수 있습니다.

### 저장 구조 및 접근 규칙

기존 계정별 `users/{uid}/folders`의 예약 접두사 `__mymo_history__` 아래에 복원 시점·내용 조각·기준 시각·lease를 저장합니다. 일반 폴더 조회는 문서 ID 범위 쿼리로 이 영역을 제외하므로 일반 동기화에서 전체 이력을 반복해서 내려받지 않습니다. 별도 컬렉션 권한을 추정해서 우회하지 않고 기존 계정 경로를 사용합니다. 실제 Firebase 접근 규칙은 해당 사용자의 인증된 접근만 허용해야 합니다.

공식 제약: [Firestore 무료 한도 및 유료 TTL](https://firebase.google.com/docs/firestore/pricing), [Cloud Functions 요금제 제약](https://firebase.google.com/docs/functions/quotas).

## 주요 코드

- `src/db/`: 계정별 DB, 원자적 로컬 쓰기, 삭제 기록, 순환 복구
- `src/stores/pages.ts`: 페이지 생성·수정·이동·휴지통
- `src/stores/persistence.ts`: 대기 중인 기기 저장과 오류 상태
- `src/stores/syncEngine.ts`: 전송 수단과 독립된 충돌·삭제·재시도 처리
- `src/stores/sync.ts`: Firestore 전송, 실시간 구독, 상태 표시
- `src/history/`: 계정 보관·중복 제거·만료 정리·페이지별 원자적 복원
- `tests/data-safety.test.ts`: 실제 Dexie 트랜잭션을 사용하는 회귀 테스트. 서버는 메모리 구현으로 대체하므로 실서비스 계정이나 자료를 수정하지 않습니다.
